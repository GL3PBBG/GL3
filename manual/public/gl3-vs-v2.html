01 · Structural

Where GL3 wins outright

These are not preferences. V2 is architecturally incapable of the guarantees on the right, and its own installed base has hit every one of them.

ConcernV2GL3
Referential integrity Zero foreign keys. Bare int(11) joined by convention. Real dumps carry orphans. 47 tables, FKs enforced, drift-guarded by a test that counts them per ON DELETE rule.
Money Signed 32-bit — caps near 2.14B. Long-running games hit it. bigint throughout, one ledger row per movement, sum(ledger) == balance asserted.
Concurrency Read-modify-write, no locking. Two requests can double-spend. Documented lock graph, 7 ABBA regression tests, at-least-once job idempotency keys.
Passwords sha256(U_id . plaintext) — unsalted beyond the user id, no work factor. argon2id with lazy upgrade from the legacy hash; reset kills every session on the account.
Realtime Server-rendered Handlebars, jQuery, one small ajax.js. A WebSocket bus with 23 typed core events. Combat, crimes, the economy, gangs, mail and notifications all arrive pushed — a battle updates both players' screens without either one asking. Countdowns tick locally and issue no request at all. Four polls survive, each because there is nothing to push: presence has no event variant, a detective's reveal is deliberately silent to its target, a seated casino table backstops its own lazy clock, and jail/hospital re-check every 30s only while you are serving, as a net for a dropped socket.
Documentation One README.md. A published manual split tutorials / how-to / reference / decisions / operators, carrying architecture decision records — and a DTO reference generated from the shipped zod schemas, so the plugin-facing contract cannot drift from the code.
Verification No test suite of any kind. 240 test files against real Postgres and Redis — no mocks on DB, queue or bus paths.

Credit where it is due: V2 uses PDO prepared statements throughout. It is not SQL-injectable, which is more than many scripts of its era manage.

02 · Parity

The gaps, closed

Successive passes of this audit named eight things V2 did better. Every one of them is now closed.

GapStatusWhat landed
Theming closed 8 themable CSS variables, presets, nav position, public endpoint so login is themed too. And with a headless posture, an operator wanting different markup writes a client rather than forking templates — which is strictly more power than V2's folder swap.
Premium membership closed Typed membership.benefits filter point, four consumers carrying V2's own numbers (×0.75 crime cooldown, ×0.25 travel fare, +10% steal), gifting, admin CRUD, V2 migration path.
Plugin install closed PLUGIN_PACKAGES + PLUGIN_DIR: a package resolved from a mounted volume at boot, manifest validated at runtime. No image rebuild — which the Docker deploy previously made impossible.
Extension surface closed 5 → 12 filter points, five of them core-owned UI seams — core.profileView, core.dashboard, core.hud, core.menuBadges, core.moneyFormat — plus inventory.itemActions. Six live subscriptions across four plugins, so the seams are exercised rather than merely declared. Each point carries its own failure policy, and each subscriber now runs under its own plugin's ctx rather than the applier's.
Rich text closed Markdown with live preview on every surface a player writes on — forum, mail, bios, gang pages, news — through marked with DOMPurify running last over its output, so raw HTML in the source is scrubbed alongside anything markdown generates. Usernames render as profile links throughout.
Item effects closed The last partial, now whole. inventory.itemEffects is a registry: a plugin declares a consumable effect kind with its own label and apply, and the built-in heal is merely the seed entry. A duplicate kind throws at boot rather than letting subscriber order decide which def runs. That is V2's itemEffects hook, typed — alongside inventory.itemActions for its itemActionLink.
Player search closed GET /api/players/search, wired to a live search box.
Game statistics closed Not a port but a replacement: money in circulation across every player, live population, jail and hospital counts, and fourteen-day series for signups, crimes and money moved — charted, with the underlying numbers expandable beneath. V2's stats module showed a handful of figures.

Past parity

Parity was the goal; it is not the ceiling. Three capabilities have no V2 counterpart at all.

CapabilityV2GL3
Multiplayer casino Blackjack exists — 411 lines, and no notion of a seat, a table or another player. You play the house alone. Seats at a shared table: sit, bet, act, leave over one hand, with a lazy clock that deals, auto-stands and settles on any read. The lobby counts who is seated per town, so a busy table is visible from a town you are not standing in.
Organized crime No such module. Four-role heists with buy-in escrow, resolved by one seeded job into a shared outcome — an equal-split payout or a mass jailing.
Game art One column, US_pic: a player's own avatar. No content table carries an image. Content-addressed assets bound per entity and per page, so items, cars, towns and ranks all take art — and the sha is the storage key, making dedup and immutable caching free.

03 · Divergences

Three things GL3 does differently on purpose

No feature gap remains, so what is left is disagreement — three places where GL3 looked at what V2 does and chose otherwise. All three are recorded in the source, not discovered here.

Installing a plugin

A V2 admin uploads a zip through the browser and the module is live. A GL3 operator installs the package into a directory the server reads — npm i --prefix /data/plugins @acme/plugin-x, typically an init container beside the one that already runs migrations — sets PLUGIN_PACKAGES and PLUGIN_DIR, and restarts.

That is not a downgrade dressed as a tradeoff. A server that fetches packages at boot needs a toolchain and registry credentials in the runtime image, and gains a boot that can fail on a network blip, a registry outage or a yanked version — and that can silently resolve differently than it did yesterday. GL3's boot reads a directory that is already populated: same restart, same code, every time. The install is a step someone audits, pins and scans, rather than an upload that is live before anyone has read it.

The convenience gap is also smaller than it appears, because the operator it was for does not exist here. V2 was FTP-and-cPanel shared hosting, where an admin might genuinely have only a browser. GL3 ships as a container: whoever deployed it can already reach a shell. Scoring V2's web uploader as an advantage imports its operator into a world that does not have them.

Death, and what it costs

V2's kill is terminal — the dead module, U_status, the newUserRevive hook. An earlier pass counted that as a parity gap. It isn't one. The genre is the Persistent Browser-Based Game; an engine that deletes the persistent thing is arguing with its own defining adjective.

GL3 keeps the stakes and drops the churn. Dying costs you every dollar you are carrying — the killer takes the victim's entire on-hand cash — plus every property you own, game-wide, a hospital stay, and any bounty on your head. The bank is untouched, which is what makes depositing real counterplay rather than an idle button. What death does not do is end the account.

The split in where the loot goes is the design: cash to the killer, property to the market. Seized rows go unowned at cost = 0, buyable by anyone. So a kill pays out liquid and does not hand over compounding assets.

That is a deliberate divergence from V2, recorded in seizure.ts: V2's userKilled hook transfers the dead player's properties to the shooter. GL3 refuses — the shooter already takes the payout, and a franchise on top compounds a winner's lead. V2 rewards the snowball; GL3 breaks it.

Rounds, and what they wipe

The same contract is broken a second time in V2, harder. Ending a round runs the clearRound hook, whose shipped subscribers TRUNCATE four tables outright — gangs, garage, userInventory, mail. Every item, every car, every gang, every message, gone. Then login.inc.php checks your U_round against the current one and, if it does not match, refuses the login with “The round is over, please register again!” Admins are exempt. Everyone else has an account they can no longer reach.

That is not a stat reset. It is the deletion of the player, in a genre whose first word is persistent.

GL3 keeps the competition and drops the wipe, by scoring the delta rather than the total. round_entries snapshots cash_at_start, bank_at_start and exp_at_start when you enter a season; your standing is (final ?? current) − start on each. The schema comment says it outright: “A round is a scoring window, not a wipe.”

So a ten-year veteran and a player who registered this morning compete on the same board — what is measured is what you did this season, not what you have. Nothing is deleted to make that true. And it cuts both ways: withdraw 500K from the bank and your bank delta is −500K for the season. It lands on the cash board as +500K, because the three boards score separately — which makes moving money between balances a visible choice rather than a free action.

04 · Verdict

Who wins

GL3 wins on engineering, and it is not close. It is a correct implementation of a game whose original could not be correct about money or concurrency even in principle — no transactions on economic paths, no foreign keys, no locking, no tests, and a money column that overflows on exactly the long-running games the engine was built to host.

V2's advantage is gone, not merely narrowed. The strongest case for it was always the extension surface: 43 hook names meant a stranger could change more of V2 than of GL3, and that was true while GL3 had five filter points. It has thirteen now — five of them core UI seams with real subscribers, each carrying its own failure policy and running under its own plugin's identity — plus a registry that lets a plugin define a new kind of item effect, which was the last thing V2's hook system could do that GL3's could not. No feature gap survives.

For an operator weighing a migration, there is no longer a category where staying is the better call. What is left is not a gap but a disagreement — three deliberate divergences, each of which GL3 can defend on its own terms. The only practical question is how much of their own module they would need to rewrite against a typed surface instead of a duck-typed one.
